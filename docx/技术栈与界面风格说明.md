# AI 学习助手技术栈与界面风格说明

版本：v1.0  
最后更新时间：2026-01-17

---

## 一、整体架构与技术栈选择

### 1.1 前端：Flutter

- 用途：实现移动端（Android / iOS）以及可选的桌面端（Windows / macOS）统一界面。
- 原因：
  - 一套代码多端运行，新手只需要学习一套 UI 框架。
  - Flutter 对动画、流畅度支持优秀，适合实现「丝滑交互」「自然动效」。
  - 组件生态丰富，便于实现复杂布局和自定义控件。

主要使用：

- `Material 3` + 自定义主题（浅色为主，非传统「科技蓝+霓虹紫」的 AI 配色）
- `Riverpod` 或 `Provider` 作为状态管理（可根据团队熟悉程度选择其一）
- `Dio` 作为网络请求库，负责调用后端接口
- `flutter_hooks`（可选）优化状态与生命周期处理

### 1.2 后端：Python + FastAPI

- 用途：提供所有 RESTful 接口、调用大模型服务、管理用户与会话、生成思维导图结构。
- 原因：
  - 语法简单，适合新手团队学习与维护。
  - FastAPI 接口声明简洁、自动生成 Swagger 文档，方便调试。
  - 对异步 IO 支持良好，适合与大模型服务进行高并发交互。

关键依赖：

- `fastapi`：构建 Web API
- `uvicorn`：作为 ASGI 服务器
- `sqlalchemy`：数据库 ORM
- `pydantic`：数据校验与序列化

### 1.3 数据库与存储

- 主数据库：PostgreSQL
  - 用于存储用户信息、会话记录、消息内容、思维导图、笔记等。
  - 支持 JSON 字段、扩展性强，结构化和半结构化数据都能很好处理。
  - 新手阶段可以只使用一个 PostgreSQL，不再引入额外的缓存组件，减少学习成本。

### 1.4 大模型接入层

为了支持「多个模型」，在后端设计一个统一的「模型适配层」。  

- 对上：对前端只暴露一个统一的接口（例如 `/conversations/{id}/messages`）。
- 对下：对不同厂商、不同协议、不同能力的大模型做适配。

可能接入的模型类型：

- OpenAI 兼容接口模型（如 GPT 系列）
- 国内厂商模型（如百度文心、讯飞星火等）——可用抽象类统一封装
- 本地部署模型（如通过 `vLLM` 或 `text-generation-inference` 暴露接口）

通过这一层，将「换模型」的复杂度留在后端，对前端而言只是换一个 `model_id`。

### 1.5 部署与运维（简述）

- 后端：使用 Docker 部署 FastAPI 服务，Nginx 做反向代理与 HTTPS。
- 数据库：PostgreSQL 独立实例。
- 日志 & 监控：使用简单的日志收集与监控方案（如 Prometheus + Grafana 或云厂商自带服务）。

## 二、页面信息结构与导航设计

整个应用的页面结构遵循「学习流程」来设计，而不是传统「功能分类」。  
核心流程是：**进入 → 选择场景与模型 → 对话学习 → 结构化整理 → 回顾与复习**。

主要页面：

1. 欢迎与登录注册页
2. 主工作区（对话 + 场景选择）
3. 思维导图视图
4. 学习笔记与收藏
5. 个人设置与偏好

页面之间的关系是一个「呼吸节奏」：

- 登录页比较简洁、平静，减少干扰，让用户完成登录。
- 主工作区是使用时间最长的地方，视觉上不喧宾夺主，重点突出对话区域。
- 思维导图页面在视觉上稍微「放大」节奏，有更明显的层次与空间感，让用户感到「知识在眼前展开」。
- 笔记与设置页面保持轻量，不打断用户主要的学习流程。

## 三、界面基调与配色风格

### 3.1 非「AI 特色」的自然配色

本项目刻意避免常见的「霓虹紫 + 深蓝渐变 + 电路板线条」式的 AI 配色。  
我们希望界面更像一本质感细腻的纸质笔记本，或者一张铺在书桌上的牛皮纸，而不是充满金属感的未来实验室。

主色调建议为「柔和的暖色系或中性色系」，例如：

- 背景色：略带暖色调的浅米白（类似 0xFFF9F5EF）
- 强调色：轻盈的湖水绿、浅薄荷绿或雾霾蓝，用于按钮、高亮标签
- 文本色：深灰而非纯黑（避免对比过于硬，阅读疲劳）

这种配色有几个好处：

- 在长时间阅读与学习中更加舒适，不刺眼。
- 亲切而不冷漠，让 AI 更像一个温和的学习伙伴，而不是「冰冷的机器」。
- 为后续的动态效果留出空间，不会因为背景太炫而抢戏。

### 3.2 光线与层次感

界面整体视觉上强调「软光感」而非强烈的高反差阴影。  
可以使用：

- 大面积的柔和背景色
- 少量高斯模糊与半透明卡片
- 很轻的投影，用来区分前后层次，而不是制造强烈的立体感

当用户打开应用时，就像掀开了一层轻薄的半透明纸页，下面铺着安静而有秩序的内容。  
在这个基调下，后续所有的动效都不再是炫技，而是像纸张被翻动、墨水缓缓晕开一样，自然、顺势发生。

## 四、交互风格与细节动效设计

这一部分是整个产品的灵魂。我们希望它不是「炫酷的 AI 工具」，而是一个「有呼吸感的学习搭档」。  
下面按几个典型场景拆解。

### 4.1 翻页时的「风吹感」

在几个关键场景中会引入「翻页与风」的隐喻：

1. 从登录完成进入主工作区的那一刻  
2. 从对话区切换到思维导图视图  
3. 在历史会话列表中切换不同会话

动画设计思路：

- 并不是传统意义上「一整页硬朗地翻过去」，而是更像轻风吹起一角，纸页稍微鼓起，然后自然滑向另一侧。
- 在 Flutter 中可以通过：
  - `PageRouteBuilder` + 自定义 `Tween<Offset>` 实现轻微的平移与淡入淡出；
  - 叠加一个略有弧度的剪裁（clip）或形变，模拟纸页被风轻轻拱起的感觉；
  - 过渡时间控制在 250–350ms 之间，配合缓动曲线（如 `Curves.easeOutCubic`）。

感受描述：

- 用户不会感到「被强制拖着走」，而是像自己轻轻翻过一页，看到下面新的内容。
- 动画结束得略微比用户预期早半拍，让界面显得干脆利落，而不是拖泥带水。

### 4.2 文本框的「流动感」

输入框是用户与 AI 接触最频繁的控件，也是情感氛围需要最用心的地方。

设计目标：

- 在用户光标移入或点击输入框时，界面给出一种「墨水开始流动、思绪开始展开」的感觉。

具体表现：

- 默认状态：输入框边缘采用非常淡的描边，配合略高于背景的柔和填充色，形状略带圆角但不过分可爱。
- 悬停（Web/桌面端）或聚焦（点击）时：
  - 边缘的一圈高亮颜色不是一次性全部亮起，而是从光标所在处像水波一样向两侧缓缓扩散；
  - 这一圈高亮可以带一点渐变，从强调色慢慢过渡到透明，就像薄薄的墨晕；
  - 背景填充色微微提亮 3–5%，模拟纸张被手指压住、纹理更清晰的感觉。

在实现上：

- 可以使用 `AnimatedContainer` 或 `TweenAnimationBuilder`，通过边框颜色与阴影的渐变来实现水波扩散；
- 也可以使用 `ShaderMask` + 动态渐变，实现更细腻的「流动光」效果（但要注意性能）。

用户体验：

- 当手指落在输入框时，界面给出的反馈是一种很微妙的「欢迎你来思考」的邀请，而不是闪瞎眼的荧光边框。

### 4.3 对话气泡的节奏感

对话区域是信息密度最高的地方，需要在「阅读效率」与「视觉呼吸感」之间取得平衡。

设计策略：

- 用户消息和 AI 消息采用不同的背景层次，但颜色差异控制在柔和范围内，避免「一边亮、一边暗」的对峙感。
- 每条消息的出现不是瞬间闪现，而是包含两个细节：
  1. **渐显**：从 0% 到 100% 的透明度变化，持续约 120–180ms；
  2. **轻微上浮**：在出现时从略微下方（例如 4px）上移到最终位置，像泡泡从水底轻轻浮上水面。

打字机效果：

- AI 回复的文字可以采用「逐字出现」的打字机效果，但速度略快于一般产品（避免焦躁感），并且允许用户点击「立即显示全部」。
- 字符出现的节奏应略有「呼吸感」，比如每句结束时稍微停顿一下，再继续下一句，仿佛对面的人在思考下一句话怎么说。

这样的设计会让用户感觉对话在「慢慢展开」，而不仅仅是文本瞬间砸在屏幕上。

### 4.4 思维导图的展开与收拢

思维导图页面是整个应用中「动态感」最集中的区域。  
目标是让用户感到「知识在眼前逐渐生长」。

生成脑图时：

- 起点是一个居中的根节点，略大一点的圆角矩形或柔和圆形，内部文字是当前学习主题。
- 根节点出现时有一个短暂的缩放动效（从 0.9 到 1.0），就像心脏轻轻跳了一下。
- 随着后端返回的树形结构，子节点并不是一次性全部出现，而是按层级、成组出现：
  - 第一层子节点从根节点的上下左右轻柔地「滑出」，配合淡入；
  - 每一层之间的动效间隔控制在 80–120ms，不要过长，主要是强调「逐层展开」的方向感。

用户手动收拢或展开某个节点：

- 节点收拢时，其子节点不是硬生生消失，而是先往父节点方向轻微回缩，再渐隐，像写在草稿纸上的分支被慢慢抹掉。
- 展开时则相反，像从父节点中「长出」新的枝条。

背景层：

- 整个脑图区域的背景采用略微有纹理感的浅色（可以模拟纸张细颗粒纹理），但纹理强度要非常低，更多是一种潜意识感受。
- 缩放与拖拽操作中，节点和连线要保持极高的流畅度，避免卡顿破坏整体「丝滑」印象。

### 4.5 登录与注册流程的自然引导

登录注册页面的设计强调「无压力」，避免让用户觉得这是一道「必须完成的考题」。

视觉：

- 背景使用非常浅的渐变，类似从柔和米白过渡到几乎不可察觉的浅绿色或浅蓝色，像窗外微微透进来的晨光。
- 中央的卡片是半透明的玻璃质感（glassmorphism），但模糊半径要适度，避免太「科技展台」的炫目感。

交互：

- 当用户从「登录」切换到「注册」时，卡片内部不是瞬间替换，而是左右轻轻滑动，仿佛翻页；  
  也可以在两个表单之间使用轻盈的交叉淡入淡出。
- 文本框获得焦点时，除了前面提到的「流动感」，整体卡片会做非常轻微的抬升，用阴影变化暗示「注意力集中在这里」。

反馈：

- 错误提示语气尽量温和，如「似乎密码有点短，再试试至少 8 位？」而不是「密码格式错误」。
- 成功登录后，不必展示复杂的成功页，而是在主工作区淡入的同时，让登录卡片像一页被合上的书，轻轻缩回到背景中。

## 五、信息层级与排版细节

### 5.1 字体与字号

为了让长时间阅读更轻松：

- 标题采用稍大字号，但不需要过于粗重，避免「喊叫」的感觉；
- 正文采用中等字重（如 `FontWeight.w400`），行高略大于默认值（如 1.4–1.6），减少阅读压迫感；
- 代码块或公式部分可以使用等宽字体，并在背景上稍作区分，但颜色保持柔和。

### 5.2 白空间的使用

整个界面要有足够的留白，让内容「能呼吸」：

- 对话气泡之间留有均匀间距；
- 不同模块之间用对齐和间距来区分层级，而不是依赖粗线条和重色块；
- 顶部导航栏高度适中，避免「压」着下面的内容。

### 5.3 图标与装饰元素

图标风格：

- 线性图标为主，线条略带圆角，与整体圆润的方块、卡片风格保持一致；
- 避免使用过多的「机器人头像」「芯片」「电路板」等传统 AI 符号，而使用更贴近学习场景的元素：
  - 书页、笔记、便签、铅笔、荧光笔、折角书签等。

装饰元素：

- 在重要的转场或空状态页面，可以使用轻描淡写的插画，如：
  - 一叠略微翻开的书；
  - 几张被风吹起的便签纸；
  - 一支轻轻靠在纸上的铅笔。

这些元素都应避免过于卡通化，以保持整体的成熟与安静感。

## 六、动态与性能平衡

虽然我们重视动效和流动感，但也必须控制好技术实现的复杂度和性能消耗，以适应新手团队和比赛时间限制。

实现策略：

- 把动效分为「核心动效」和「可选动效」：
  - 核心：翻页风吹感、输入框流动感、对话气泡渐显与上浮、脑图逐层展开；
  - 可选：更复杂的水波光效、纸张纹理动态变化等。
- 优先保证核心动效流畅稳定，再视时间和性能决定是否添加可选动效。

技术实践：

- 尽量使用 Flutter 自带的隐式动画组件（如 `AnimatedContainer`、`AnimatedOpacity`、`AnimatedPositioned`），实现成本低，性能表现好；
- 少量使用显式动画控制器，仅在必要的复杂场景中使用；
- 定期在中低端设备上测试滚动和缩放性能，确保不会因大量阴影和模糊导致掉帧。

## 七、总结：整体体验气质

从技术上看，这是一个 Flutter + Python + FastAPI + PostgreSQL + 多模型接入的典型 AI 应用架构；  
但从体验上，我们希望它更像一个「安静、温柔、细腻」的学习空间，而不是闪光灯下的科技秀场。

用户打开应用时，看到的是一张轻微发光的纸，而不是一块冰冷的玻璃；  
他们在输入问题时，感受到的是墨水在纸上慢慢扩散，而不是屏幕闪烁；  
他们生成脑图时，看见的是知识的枝叶一层层伸展开来，而不是几何图形突然堆满屏幕。
